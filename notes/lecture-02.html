1. Floating-point systems, formally

A floating-point system is written $\mathbb{F}(\beta, p, L, U)$. Any normalized nonzero number in it looks like

$$x = \pm\left(d_0 + \frac{d_1}{\beta} + \frac{d_2}{\beta^2} + \cdots + \frac{d_{p-1}}{\beta^{p-1}}\right)\beta^{E}, \qquad L \le E \le U,$$

with $d_0 \ne 0$ and each digit $d_i \in \{0, 1, \ldots, \beta-1\}$.

SymbolMeaning
$\beta$Base — typically 2 for binary floating point.
$p$Precision: number of significant digits in the significand.
$L$Lower exponent bound.
$U$Upper exponent bound.
IEEE single precision $$\beta = 2, \qquad p = 24, \qquad L = -126, \qquad U = 127.$$ The spacing between representable numbers is not constant — the same significand patterns repeat at every exponent, so the absolute gap between neighbors grows with magnitude even though the relative precision stays fixed.

2. Representation error and machine precision

For a real number $x \in \mathbb{R}$ inside the representable range, there is a unique floating-point approximation $\hat{x}$ satisfying

$$\exists!\,\hat{x}\in\mathbb{F} \quad \text{s.t.} \quad |x-\hat{x}| \le \varepsilon_{\mathrm{machine}}\,|x|,$$

where the representation error (also called round-off error) comes from rounding $x$ up or down to the nearest representable value, and machine precision is

$$\varepsilon_{\mathrm{machine}} = \beta^{1-p}.$$

This is a genuinely different quantity from the smallest positive normalized number, $x_{\min} = \beta^L$. Machine precision governs relative spacing near a given magnitude; $x_{\min}$ is set entirely by the lower exponent bound.

Worked example — rounding $x = 5.3$ In the same toy system as last class ($\beta=2,\ p=3,\ L=-1,\ U=2$), the nearest representable value to $x = 5.3$ is $\hat{x} = 5$: $$\hat{x} = 5, \qquad |x - \hat{x}| = 0.3000.$$ Here $\varepsilon_{\mathrm{machine}} = 2^{1-3} = 0.25$, so the bound $\varepsilon_{\mathrm{machine}}|x| = 1.325$ comfortably covers the actual error of 0.3 — the bound is a worst case, not a tight prediction of any one rounding.

4. Catastrophic cancellation and associativity

Take six significant decimal digits and

$$a = 1.23456\times10^2, \qquad b = -1.23455\times10^2, \qquad c = -1.11123\times10^{-3}.$$

Over the real numbers, $(a+b)+c = a+(b+c)$ exactly. Under finite precision, the two evaluation orders don't have to agree, because nearly-cancelling numbers can wipe out significant digits, and every later operation proceeds from that already-degraded intermediate result.

Concrete arithmetic, rounded to $p$ significant decimal digits at each step $(a+b)+c$: $123.456 - 123.455 = 0.00100 = \operatorname{fl}(a+b)$, then $0.00100 - 0.00111123 \approx -1.1123\times10^{-4}$.

$a+(b+c)$: $-123.45500000 + 0.00111123 \approx -123.456 = \operatorname{fl}(b+c)$, then $123.456 - 123.456 = 0$.

Same three numbers, same mathematical expression, two different stored results — a difference of $-1.1123\times10^{-4}$ purely from parenthesization. Floating-point addition is not reliably associative: the order you group operations in changes which intermediate values get rounded, and that can change the final answer.

5. Case study: the quadratic formula

Consider $ax^2 + x - 1 = 0$, with exact roots

$$x_{\pm} = \frac{-1 \pm \sqrt{1+4a}}{2a}.$$

For $a = 10^{-4}$, the true roots are $x_+ \approx 0.999900019995$ and $x_- \approx -10000.99990002$. The cancellation problem lives entirely in $x_+$: for small positive $a$, $\sqrt{1+4a}$ is close to 1, so the numerator $-1+\sqrt{1+4a}$ subtracts two nearly-equal quantities and can lose most of its significant digits.

Multiplying numerator and denominator by the conjugate removes the subtraction entirely:

$$\frac{-1+\sqrt{1+4a}}{2a}\cdot\frac{-1-\sqrt{1+4a}}{-1-\sqrt{1+4a}} = \frac{2}{1+\sqrt{1+4a}}.$$

The two formulas are algebraically identical, but the rationalized version never subtracts two nearly-equal numbers, so it stays accurate even at low precision.

Naive vs. rationalized, at $p$ rounded significant digits Naive formula: $\operatorname{fl}(\sqrt{1+4a}) \to 1$ under coarse rounding, so the numerator rounds to exactly $0$.

Rationalized formula: same rounded square root, but with no subtraction of nearly-equal values — it lands close to the true reference value of $0.999900019995$.

6. The harmonic series and summation order

Consider the partial sums $H_N = \sum_{n=1}^{N} \frac1n$. In finite precision, three distinct failure modes can each masquerade as "the sum has converged":

Failure modeCondition
Increment too small relative to the running total$\operatorname{fl}\!\left(S_i + \frac1i\right) = S_i$
The term itself underflows$\dfrac1i < \beta^L$
The partial sum overflows the upper range$S_i > \beta^U$

Changing the order you add terms in never changes the true mathematical sum — but it can change the floating-point answer you get. Direct summation accumulates term by term:

$$\widehat H_N^{\mathrm{direct}} = \operatorname{fl}\!\Big(\cdots\operatorname{fl}\big(\operatorname{fl}(1+\tfrac12)+\tfrac13\big)+\cdots+\tfrac1N\Big).$$

Chunked summation instead groups terms into blocks of size $m$, sums each block, then adds the block totals: with $S_j^{(m)} = \sum_{i=(j-1)m+1}^{\min(jm,N)} \frac1i$, the block sum $B_N^{(m)} = \sum_j S_j^{(m)}$ equals $H_N$ mathematically, but is computed with a completely different association pattern in floating point.

Direct vs. chunked, low decimal precision, moderate $N$ Direct summation: 10.7625, with the first "no-op" update (where adding the next term leaves the sum unchanged) appearing around $i = 20{,}000$.

Chunked summation (blocks of 1,000, up to 300 blocks): 13.1893.

Same mathematical partial sum, different association pattern, a difference of 2.4268.
Watch out: a genuinely convergent sequence and a finite-precision sequence whose increments have simply become too small to register can both look like they've stopped changing. Observing $S_{i+1} = S_i$ tells you the machine has hit a limit — it does not by itself prove mathematical convergence.

The general diagnostic: evaluate the same mathematical quantity with more than one reasonable association pattern (direct, chunks of 500, of 1,000, of 10,000, ...). If the answers disagree substantially, the numerical result is algorithm-dependent and shouldn't be trusted as a stand-in for the true value.

7. AI coding workflow and homework

For sandboxed agent-assisted coding, GitHub Codespaces restricts an agent to a project workspace, which limits the blast radius of accidental file changes compared with giving an agent broad access to a local machine.

Homework direction Construct or analyze a series that either converges or diverges, but for which a finite-precision implementation produces a misleading numerical result. The explanation should identify the specific numerical mechanism behind the discrepancy — not just show that two computed answers differ.

Main takeaways

  • Floating-point arithmetic operates on a finite set of numbers.
  • Representable range and machine precision are separate properties, set by different parameters.
  • Absolute spacing grows with magnitude even when relative precision stays fixed.
  • Catastrophic cancellation can erase significant digits when nearly-equal numbers are subtracted.
  • Floating-point addition is not reliably associative.
  • Algebraically equivalent formulas can have very different numerical behavior — rationalizing away a subtraction is one general fix.
  • Changing the summation order is a useful stress test when the exact answer isn't known independently.
