Lecture 1 — Numerical Computing & Floating-Point Arithmetic

Friday, Sept 11 · First class · Foundations

1. Why numerical reliability matters

The question this course keeps returning to is not "does the program run?" but "is the answer right?" Code that executes without errors can still return a result that is inaccurate or inappropriate for the problem being asked. Successful execution says nothing about numerical correctness.

Uncertainty quantification is the broader discipline this sits inside: using math and computation to characterize how uncertain a result actually is. A handful of well-known engineering failures make the stakes concrete — the Therac-25 radiation overdoses, the Patriot missile failure, the Ariane 5 maiden-flight failure, and the Sleipner A platform collapse. Each involved a different mix of software, numerical, design, and validation failures, but all of them trace back to trusting a computed number without enough independent checking.

2. AI-assisted scientific computing

AI tools can generate working code fast. What they can't do is know, on their own, whether that code solves your problem correctly, handles bad inputs sensibly, or stays stable under small perturbations — that judgment is still on you. The recurring themes of this course, stability and accuracy, are exactly the things an AI-generated solution won't check for you automatically.

Learning loop for this course Understand the problem and method (implement it yourself when it helps) → generate an AI-assisted solution → validate the result against a reference → explain any discrepancy and what it revealed.

A useful habit: ask an AI assistant to implement a numerical method, then stress-test it on inputs designed to expose its assumptions — very small increments, large differences in scale, invalid values. For example, ask for a program that repeatedly adds a small number to a large one, then check whether each increment actually changes the stored value. Finding the failure, explaining why it happens, and proposing a fix is the actual skill being built here.

4. Problem formulation: well-posedness, conditioning, stability

A mathematical problem is well-posed when it satisfies three properties: a solution exists, that solution is unique, and the solution depends continuously on the input data (initial or boundary conditions). These are properties of the mathematical problem itself, independent of how — or whether — you compute it. Merely writing down the conditions a solution should satisfy doesn't establish that one exists.

Formulating a problem, proving it has a unique solution, and choosing a reliable way to compute that solution are three separate jobs. The linear system $Ax = b$ is the simplest example: writing it down, showing $A$ is invertible, and picking a numerically sound solver are each distinct steps.

ConceptObject of studyMain question
Well-posednessMathematical problemExistence, uniqueness, continuous dependence?
ConditioningProblem at given inputsHow sensitive is the solution?
StabilityAlgorithmHow do computational errors affect its behavior?
AccuracyComputed resultHow close is it to the intended answer?

Conditioning measures how sensitive a problem's solution is to perturbations in its inputs — continuous dependence (well-posedness) does not by itself imply low sensitivity. Stability is a separate concern about how an algorithm handles the errors introduced during the computation itself.

Scalar condition number For a differentiable $f$ with $x \ne 0$ and $f(x) \ne 0$, the local relative condition number is $$\kappa_f(x) = \left|\frac{x f'(x)}{f(x)}\right|.$$ Take $f(x) = x - 1$: this function is perfectly continuous, but $\kappa_f(x) = |x/(x-1)|$ blows up near $x = 1$. A tiny relative change in the input near that point produces a much larger relative change in the output — the problem is ill-conditioned there even though it's well-posed everywhere.

5. Number representation

Floating-point representation borrows the idea behind scientific notation: $123456 = 1.23456 \times 10^5$ and $0.00568 = 5.68 \times 10^{-3}$. The sign of the number and the sign of the exponent play different roles — a negative exponent rescales the magnitude, it doesn't make the value negative.

In positional notation, each digit contributes its value times a power of the base. The binary number $(101.01)_2$ means

$$5.25 = 1\cdot2^2 + 0\cdot2^1 + 1\cdot2^0 + 0\cdot2^{-1} + 1\cdot2^{-2},$$

and its normalized form is $(1.0101)_2 \times 2^2$, using five significant binary digits.

A general normalized floating-point number takes the form

$$x = s\,(d_0.d_1\ldots d_{p-1})_\beta\,\beta^{e}, \qquad d_0 \ne 0,$$

built from a sign $s \in \{-1, +1\}$, a base $\beta$, a precision $p$ (the number of significant digits kept, including the leading one), digits $d_i \in \{0, 1, \ldots, \beta-1\}$, and an integer exponent $e$ bounded by $L \le e \le U$. For a normalized nonzero number the leading digit $d_0$ can't be zero — in binary that forces $d_0 = 1$. Zero is stored as a special case.

6. A toy floating-point system

To make all of this concrete, take the smallest system that still shows the interesting behavior: $\beta = 2$, $p = 3$, $L = -1$, $U = 2$. The significand has three binary digits,

$$(1.d_1d_2)_2 = 1 + \frac{d_1}{2} + \frac{d_2}{4},$$

giving four possible significands: $(1.00)_2 = 1$, $(1.01)_2 = 1.25$, $(1.10)_2 = 1.5$, $(1.11)_2 = 1.75$. Multiplying each by every allowed power of two gives all 16 positive representable values (16 negative counterparts plus zero complete the system — 33 numbers total).

Range and spacing

For a normalized system, the smallest and largest positive representable magnitudes are

$$x_{\min}^{+} = \beta^L, \qquad x_{\max} = (\beta - \beta^{1-p})\,\beta^U,$$

and within a single exponent block the spacing between neighbors is

$$\Delta_e = \beta^{\,e-p+1}.$$

For our toy system, $x_{\min}^{+} = 0.5$, $x_{\max} = 7$, and $\Delta_e = 2^{e-2}$: raising the exponent by one doubles the spacing, while raising the precision by one halves it at a fixed exponent. Range and exact representability are different things — 4.625 sits well within this system's range but falls between two representable values, while 8 would need exponent 3 and is simply out of range.

Watch out: a terminating binary expansion requires a denominator that's a power of 2. So $1/8 = (0.001)_2$ terminates, but $1/10 = (0.000110011\ldots)_2$ repeats forever — no amount of extra binary precision makes 0.1 exactly representable.

7. Numerical errors

Two distinct sources of error show up even before you get to a full computation.

StageSource of error
Input representationThe original value simply isn't available in the number system.
Arithmetic operationThe exact result of an operation on two representable numbers isn't itself representable.

Let $\operatorname{fl}(x)$ denote the rounded machine representation of $x$. In the toy system, the smallest positive value is 0.5, so $\operatorname{fl}(0.1) = 0$ — 0.1 simply falls in the gap near zero. Both 4 and 0.625 are exactly representable, yet $4 + 0.625 = 4.625$ is not: $\operatorname{fl}(4+0.625) = 5$, an arithmetic rounding error of $5 - 4.625 = 0.375$, even though neither input carried any representation error at all.

Order of addition matters Using the toy system's midpoint rule, 4.5 rounds to 4, so $\operatorname{fl}(4+0.5)=4$ — a nonzero increment can leave the stored value completely unchanged. That has a real consequence for the order you add things in: $$\operatorname{fl}\bigl(\operatorname{fl}(4+0.5)+0.5\bigr) = 4, \qquad \operatorname{fl}\bigl(4+\operatorname{fl}(0.5+0.5)\bigr) = 5.$$ The first order loses both increments separately; the second combines them into 1 before ever touching the 4. Floating-point addition is not generally associative.

Validation checklist

  • Check whether the mathematical problem is well-posed in the first place.
  • State the assumptions your computational method introduces.
  • Separate input representation errors from arithmetic errors.
  • Compare against an analytic answer or an independent calculation.
  • Explain how precision, input scale, and operation order affected the result.
